Your team's task is to write 1 C++ program that performs different
cryptographic tasks for Alice and Bob:

### 1. 📊 Text Decryption + Analysis

🎥 Watch video: [**polyalphabetic ciphers**](https://www.youtube.com/watch?v=BgFJD7oCmDE&list=PLSQl0a2vh4HA50QhFIirlEZRXG4yjcoGM&index=7).

Your team has been given an encrypted text in the `hackathon1/texts` folder of the
Github. Your task is to write code that helps you decrypt the text. The text
has been encrypted by Alice using a **Vigenère cipher**. The letters have
been placed into groups of 4 so that the word breaks are disguised. The
**key** is one of the words listed in a file called `keys.txt` in the
same `hackathon1` folder. This file is also uploaded in the zyBooks lab 16.40.

This part of your program should do the following:
- make use of the methods shown in **zyBooks 9.5** (new for this week)
- output a **frequency analysis** showing the counts of every letter of your team's encrypted text
- output the correct key that you discovered
- output the correct original (decrypted) English plaintext
- output a description of the context of this plaintext - where is this text from, and what does it mean? what does your team think of this text?

On the backend, your program's logic should suggest to the user which key is most likely correct, given what you know.
The approaches for this range from simple to highly sophisticated (_partial credit will be awarded here for attempts_) ... 
Research about ciphers and crytographic methods is encouraged here!

### 2. 🔒 Encryption

🎥 Watch video: [**one-time pad**](https://www.youtube.com/watch?v=FlIG3TvQCBQ&list=PLSQl0a2vh4HA50QhFIirlEZRXG4yjcoGM&index=9)

Your program should take an input text from your user, and then encrypt
that text **with an encryption algorithm of your own design.** The steps
of your encryption need to be reversible; for example, if Alice encrypts
the message and Bob knows the key, Bob should be able to decrypt it.

This part of your program should output the encrypted text and the key.

Other requirements:
- your encryption should make use of a pseudorandom number generator **of
your own design** - **not** `rand()`
- your encryption should be partially inspired by the one-time pad - how can you make use of this method?
- your method can have multiple layers and operations - creativity will be rewarded!
- your team should add comments to this part of the code, clearly explaining the encryption process you devised
- the goal here is _not_ to pull in someone else's pre-existing algorithm, but to create your own with your team, using math that you know. Remember,
encryption is just scrambling data with math.

### Program Design

Your program should be in 1 `cpp` file. Your user should be able to choose
which task (Part 1 analysis/decryption, or Part 2 encryption) that they
want to perform, like a menu of options.

Beyond these requirements listed, the implementation is up to you!

Your team's final code will be evaluated on:
